# 墨习 · 查字与书写笔记

v0.5.1 修复播放时名称大量缺失：除原有 25 字的有限核对名称外，新增 CNChar 笔顺名称参考。当前有 8610 字的名称数量与动画笔画数一致，可显示“名称参考（待核对）”；数量一致不证明两套数据顺序相同。有多个叫法时显示候选，数量不符或缺失时不套用。整字类型检索保持独立。

墨习是可部署到 GitHub Pages 的汉字学习工具。v0.5 查字后自动汇总全部相关笔画、偏旁部首与间架结构笔记；整字笔画类型不再依赖逐笔选择。笔记用途为整字、偏旁、结构和笔画，支持自定义分类、个人修订及 JSON 导入导出。页面、字库和动画资源均自托管，个人笔记保存在当前浏览器。

本版提供可选的 AI 间架结构分析。用户可随时设置或切换完整调用地址、模型与密钥；不配置接口也能查字、播放动画和管理笔记。本版没有 PDF 导入、AI 对话或临摹画板入口。旧版教材摘要、PDF 渲染代码与 Worker 接口留在源码中，不进入新版构建。

## 数据与学习边界

- 字形快照共 **9574 条记录**，包括简体和繁体；不表示覆盖全部汉字、异体字或所有地区笔顺规范。
- 动画与参考字形来自 Make Me a Hanzi / Arphic 开源数据，不是卢中南或其他书家的真迹。没有轨迹的字不使用模型或设备字体补造笔顺。
- **整字笔画类型参考**取自 CNChar 3.2.6，覆盖上述字库中的 **8776 字**；另 **798 字**没有类型参考，保持未知。文件为 `data/stroke-types.json`。它只用于汇总本字涉及的类型，不与动画第几笔对齐，也不判断某一横是长横还是短横。
- CNChar 部分编码对应多种名称，类型库保留这些候选并记录歧义；列出候选不表示这些类型一定同时出现在该字中。原名称“点2”合并为检索标签“点”，不表示实际形态完全相同。
- **有限逐笔名称参考**为独立的 `data/stroke-names.json`，只覆盖 25 个已做有限核对的常用字，用于单笔观察状态。歧义名称留空；它不限制整字笔画笔记的自动汇总，也不能作为全部笔序已认证的证明。
- 部首、IDS 拆分与结构分类是参考资料。未知偏旁或待核对项目会保留不确定性；不据此生成确定的空间比例、笔锋或力度结论。个人修订不冒充上游事实。
- AI 分析是单独标记的结构推演，可能出错，不是教材原文、规范认证或书家特点；不会自动改写个人笔记。
- 界面宋体用于标题与阅读排版，不能当作书法家的范字。

## 查字和复用笔记

新建笔记只有一个入口：**知识库 → 新建笔记**。已有笔记可以点击“编辑”调整分类，空分类显示为“未分类”。

基本笔画使用“笔画”用途。例如分别建立对象为“长横”“短横”的笔记，分类均填“基本笔画”；再建立“横画练习”“横折对照”等分类的记录。查到包含“横”类型参考的字时，这些笔记会一次列出，无需播放或选择某一笔。系统查找所有用途的分类文字，并查找笔画用途中的目标名称；“横折钩”会关联含“横”“折”或“钩”的记录。只有标题或正文命中、分类与目标均不匹配的记录不会进入此区域，可用知识库搜索查找。

偏旁参考也自动汇总。查“河”后，已识别的“氵”“可”和字典部首会用于检索：偏旁用途的同字形目标，以及所有用途中包含该字形或固定俗名（如“三点水”）的分类。不同位置、层级和写法的记录一并列出，原位置、范围和条件保持可见。系统不把“水”和“氵”、“手”和“扌”自动合并；固定俗名按其实际字形识别。

所有这类汇总均为**相关候选**，不代表笔记中的写法已适用于当前字。结果按笔记 ID 去重、不截断，正文、来源与条件原样展示。整字仍精确关联本字；结构笔记根据字库结构参考或单独标记的 AI 结构分析关联。完整例子见 [使用指南](docs/USER_GUIDE.md)。

## 可选 AI 接口

在查字页打开 **AI 接口设置**，填写完整 HTTPS 调用地址、模型名称和 API 密钥。接口须兼容 **Chat Completions**；地址通常以 `/v1/chat/completions` 结尾，但以服务商文档给出的完整地址为准。开启“查字后自动分析”后，查字自动请求间架结构分析，也可手动点击“分析当前字”。

地址、模型与密钥可随时修改；应用新设置或切换汉字会取消旧请求，过期结果不覆盖当前字。接口出错时保留字库参考和个人笔记。请求可能产生服务商模型费用。

配置与密钥只保留在本次页面内存，刷新后重新填写，不写入 GitHub、浏览器存储或笔记备份。发给用户配置服务的资料仅为当前汉字及部首、拆分、结构参考字段，**不发送笔记或 PDF**。AI 结果在本次页面使用，不自动写入个人修订或导出备份。只填写自己信任的服务地址。

服务端必须允许网页跨域调用（CORS）。静态网页不能绕过此限制；服务商不开放浏览器调用时，可使用自己的 HTTPS、Chat Completions 兼容代理。本站没有部署模型代理，也不提供共享密钥。提供此协议支持不表示保证兼容所有模型服务的全部扩展字段。

## 保存与跨设备备份

个人资料与当前浏览器、设备和站点来源绑定，不自动云同步，也不会随 GitHub Pages 更新提交到 GitHub。换手机、换浏览器、清除站点数据或使用无痕窗口时，原笔记不会自动出现。

在“数据管理”导出全部或所选笔记，确认 JSON 文件已保存；在目标浏览器导入并核对预览，再处理新增、重复和冲突。导出保留笔记用途、分类、原文、来源和选定的个人修订；不包含整套字典、动画、PDF 或 AI 配置。存储失败时应立即导出内存中的备份，确认下载后再刷新。

v0.5 继续使用 `schemaVersion: 3`，兼容本笔记系统的 v1、v2、v3 备份。v1 缺少分类的内容归为“未分类”，v2 分类继续保留。包含笔画用途的新备份应使用 v0.4 或更新网页导入；v0.1 学习记录属于不同格式，请保留原文件。旧浏览器存储键保持保留，不为升级而清除。

## 本地运行与检查

需要 Node.js 24 或更新版本。前端没有需安装的 npm 运行时依赖。

```powershell
npm test
npm run build
npm run preview
```

打开 `http://127.0.0.1:4173`；可用 `node tools/dev-server.mjs --port 8000` 更换端口，用 `Ctrl+C` 停止。服务器只监听本机并提供 `dist/`，为 JavaScript、JSON、CSS 和 WOFF2 返回相应 MIME 类型。请通过 HTTP 服务访问，不要用 `file://` 双击 HTML。

可选 DOM 交互测试使用 jsdom 26.1.0，可在独立开发目录安装并通过 `MOXI_TEST_DEPS` 指定位置，再运行 `npm run test:ui`。缺少依赖时明确跳过；DOM 检查不能替代真实浏览器的布局、动画帧和触控验证。数据一致性测试也不能证明所有汉字的教学分类或地区笔顺均正确。

## 构建与发布

发布精确白名单为：

- `index.html`、`styles.css`、`app.js`、`model.js`、`ai.js`，以及存在时的 `store.js`。
- `data/characters.json`、`data/source-manifest.json`、`data/stroke-names.json`、`data/stroke-types.json` 和 `data/characters/` 中逐字 JSON。
- `vendor/hanzi-writer.min.js`、`vendor/fonts/moxi-book-serif.woff2` 和 `licenses/`。

`ai.js` 与 `data/stroke-types.json` 为必需文件。构建不复制整个 `data/` 或 `vendor/`；教材摘要、书目、PDF.js、`pdf-local.js`、私有配置与 `worker/` 不进入 `dist/`。先校验输入，再安全重建本项目 `dist/`，总大小限制为 50 MB；允许树内的 PDF、图片、符号链接、凭据文件或常见密钥内容会使构建失败。静态测试验证新增文件必需、精确入包、资源版本一致、旧载荷隔离、重复构建与污染输入拒绝。

仓库为 `petersmith030201/moxi-calligraphy`，默认分支 `main`。GitHub 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。推送到 `main` 或手动运行 **Deploy calligraphy site** 后，工作流运行测试，仅上传 `dist/` 并发布。通常访问地址为 `https://petersmith030201.github.io/moxi-calligraphy/`，以成功部署输出为准。模型设置由每个使用者在页面内填写，无需把模型密钥配置到 Pages 工作流。

旧版源码保留在 Git 标签中；需要查看 v0.1 时可在干净目录运行 `git worktree add ../moxi-v0.1 v0.1`。切换代码版本不自动迁移个人资料，也无需清除浏览器存储。
